# PostgreSQL init scripts — چرا این‌ها وجود دارند

دو فایل زیر در `pishdad-core/backend/docker/postgres/init/` هستند و روی **اولین** ساختِ volumeِ دیتابیس اجرا می‌شوند
(`/docker-entrypoint-initdb.d`). منبع حقیقت، خودِ `.sql` است؛ این فایل فقط دلیل را نگه می‌دارد، چون
متنِ SQL از پارسرِ گراف رد می‌شود و بدون این توضیح، دلیلش گم می‌شود.

## `01-collation.sql` — collation فارسی

`CREATE COLLATION "fa-IR" (provider = icu, locale = 'fa-IR')`

- **هدف:** مرتب‌سازیِ درستِ فارسی. بدون این، PostgreSQL با ترتیبِ بایتی مقایسه می‌کند و «ک» بعد از «گ»
  می‌آید — یعنی هر فهرستِ مرتب‌شده در پنل برای کاربرِ ایرانی غلط است.
- **چرا `IF NOT EXISTS`:** اسکریپت یک‌بار اجرا می‌شود، ولی idempotent بودن یعنی اگر دستی هم اجرا شد
  خطا ندهد.
- **چرا `EXCEPTION WHEN OTHERS`:** اگر `icu` در این ایمیج نباشد، کل init نباید fail شود؛ فقط اعلان
  می‌دهد و به collation پیش‌فرض می‌افتد. یعنی **بدترین حالت = نبودِ بهبود، نه خرابیِ نصب**.
- ⚠️ **هشدارِ بی‌ضرر:** PG16 ممکن است چاپ کند
  `WARNING: ICU locale "fa-IR" has unknown language "fa"`.
  این quirkِ اعتبارسنجیِ داده‌های ICU است و **بی‌خطر** — قواعدِ فارسی اعمال می‌شود.
  (ایمیج `icu-data-full` نصب می‌کند تا قواعدِ غیرانگلیسی حاضر باشند.)
  معیارِ پذیرش: `'ی' = 'ي' COLLATE "fa-IR"` باید `t` بدهد، برخلاف مقایسهٔ بایتی.

## `02-testdb.sql` — دیتابیسِ جدا برای تست

`CREATE DATABASE pishdad_test`

- **چرا جدا:** `php artisan test` از `RefreshDatabase` استفاده می‌کند، یعنی هرچه را مهاجرت کند
  **پاک می‌کند**. اگر روی دیتابیسِ توسعه اجرا شود، داده‌های واقعیِ نصب نابود می‌شود.
  پس تست‌ها **باید** روی دیتابیسِ خودشان اجرا شوند.
- **چرا `\gexec`:** این یک متا‌کامندِ psql است، نه SQL — یعنی `CREATE DATABASE` را وقتی لازم شد
  **اجرا** می‌کند. چون `CREATE DATABASE` داخل بلوکِ تراکنشی مجاز نیست، نمی‌شود مستقیم نوشت.
- ⚠️ **قیدِ نگهداری:** این فایل باید **LF-only و بدون BOM** بماند، وگرنه `\gexec` در حالتِ
  متنیِ psql اجرا نمی‌شود و دیتابیسِ تست ساخته نمی‌شود — و آن خطا موقعِ تست خودش را
  نشان نمی‌دهد، فقط می‌گوید «دیتابیس وجود ندارد».

## ارتباط با تست‌ها
