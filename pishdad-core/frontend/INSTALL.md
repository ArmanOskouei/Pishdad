# نصبِ فرانت‌اند

فرانت با **یک باندلِ بیلدشده** روی هر سروری نصب می‌شود. لازم نیست برای هر نصب
دوباره ساخته شود — همهٔ مقدارها در **زمانِ اجرا** خوانده می‌شوند.

## راهِ ۱ — داکر (توصیه‌شده)

```bash
cd pishdad-core/frontend
docker compose up -d
```

سپس در مرورگر:

```
http://<نشانیِ سرور>:3100/setup
```

فقط اطلاعاتِ بک‌اند را وارد کنید. پس از ذخیره، همان لحظه اعمال می‌شود؛ نه
بازسازی لازم است و نه ری‌استارت.

## راهِ ۲ — Node روی سرور

```bash
cd pishdad-core/frontend
npm ci
npm run build
node .next/standalone/server.js
```

`/setup` هم در دسترس است. اگر پوشهٔ `config/` قابلِ نوشتن نباشد، نصب‌کننده
مقادیرِ `.env` را نشان می‌دهد تا خودتان بگذارید.

## نصب‌کننده چه می‌پرسد

| فیلد | اجباری | توضیح |
|---|---|---|
| نشانیِ عمومیِ API بک‌اند | ✅ | مثل `https://api.example.com/api`. اگر `/api` را ننویسید، خودش امتحان می‌کند و پیدا می‌کند. |
| نشانیِ داخلیِ API | — | برای SSR. در داکر معمولاً `http://backend:8080/api`. خالی = همان نشانیِ عمومی. |
| نشانیِ عمومیِ سایت | ✅ | مثل `https://example.com`. در canonical، OG، sitemap و llms.txt استفاده می‌شود. پیش‌فرض از `Host` پر می‌شود. |
| زبان‌های فعال | ✅ | `fa,en` — جداشده با کاما. |
| زبانِ پایه | ✅ | مثل `fa`. بدونِ پیشوند در URL می‌آید. |
| رازِ revalidate | ✅ | همان `REVALIDATE_SECRET` در `.env` بک‌اند. باید **دقیقاً** یکی باشد. |
| دارایی‌های رسانه‌ای، کلیدِ VAPID، شناسهٔ سایت | — | بخشِ «پیشرفته». |

پیش از ذخیره، نصب‌کننده **واقعاً** به `{api}/v1/site/status` وصل می‌شود؛ اگر
نرسد چیزی نوشته نمی‌شود.

## کجا نوشته می‌شود

`pishdad-core/frontend/config/runtime.json` — روی یک volume می‌ماند تا با هر `up`
تازه از دست نرود. مسیرش با `PISHDAD_CONFIG_FILE` عوض می‌شود.

⚠️ رازِ revalidate داخلِ همین فایل است. در `.gitignore` است و نصب‌کننده
`mode: 0600` می‌گذارد.

## ترتیبِ اولویت

```
فایلِ نصب  ←  متغیرِ محیطِ CMS_*  ←  مقدارِ زمانِ بیلدِ NEXT_PUBLIC_*  ←  پیش‌فرض
```

نکتهٔ مهم که یک بار ما را گمراه کرد: **`NEXT_PUBLIC_*` در زمانِ اجرا خوانده
نمی‌شود.** Next آن را حتی در کدِ سرور با ثابتِ زمانِ بیلد جای‌گذاری می‌کند. اگر
می‌خواهید چیزی در زمانِ اجرا خوانده شود، نامش را `CMS_*` بگذارید.

## قفل

پس از نصبِ موفق، `/setup` قفل می‌شود. برای نصبِ دوباره:

```bash
rm pishdad-core/frontend/config/runtime.json
```

## اشکالاتِ رایج

| نشانه | علت |
|---|---|
| `/setup` → ۴۰۴ | مسیرِ `setup` به زبان بازنویسی شده. باید در `SYSTEM_PATHS` پروکسی باشد. |
| «به بک‌اند نرسیدم» | در داکر، `localhost` داخلِ کانتینر خودِ کانتینر است نه میزبان. از `host.docker.internal` یا نامِ سرویس استفاده کنید. |
| سایت به‌جای محتوا redirect می‌کند | زبانِ پایه و فهرستِ زبان‌ها با هم نمی‌خوانند. در `/setup` هر دو را درست بدهید. |
| پاک‌سازیِ کش کار نمی‌کند | `REVALIDATE_SECRET` فرانت با بک‌اند یکی نیست. |
