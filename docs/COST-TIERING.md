# 💰 تیربندی هزینه (Cost Tiering) — CMS اختصاصی

> تاریخ: شهریور ۱۴۰۵
> وضعیت: پیشنهاد تأییدشده — حاصل بازخورد متخصصان (یافته #۵: تک‌مستاجر × ۵ سرویس = انفجاری)

---

## 🎯 مشکل

مدل «هر مشتری = ۵ سرویس جدا (Laravel + Next + PG + Redis + MinIO)» با ده‌ها مشتری از نظر هزینه انفجاری است (هزینه خطی با ۵ ضریب). راه‌حل: **تیربندی** — کانتینرهای اپ جدا می‌مانند (اجتناب‌ناپذیر برای دامنه ایزوله) ولی لایه داده مشترک می‌شود.

## 🏗️ معماری ۳ تیره

| تیر | مخاطب | PG | MinIO | Redis |
|---|---|---|---|---|
| **Budget** | مشتری کوچک (پیش‌فرض) | PG اختصاصی مشترک (~۱۵ مشتری، ۱ دیتابیس per مشتری) | مرکزی + باکت per مشتری | مرکزی + prefix per مشتری |
| **Standard** | مشتری متوسط | PG اختصاصی per مشتری | اختصاصی | اختصاصی |
| **Enterprise** | مشتری بزرگ | PG اختصاصی + replica | اختصاصی + versioning | اختصاصی |

## ⚙️ پیاده‌سازی

### PostgreSQL چند-دیتابیس
- یک PG اختصاصی (Silver 2GB / Gold 4GB) → ۱۵ دیتابیس جدا (نه schema)
- بکاپ خودکار چابکان (چون اختصاصیه) + `pg_dump` شبانه به MinIO (بکاپ دوم، retention ۱۴ روز)
- pool اتصال Laravel: ۵–۱۰ کانکشن per مشتری (۱۵۰ از سقف ۲۰۰۰)

### MinIO مرکزی
- باکت `t{id}-media` و `t{id}-backups` per مشتری
- کلید S3 اختصاصی per مشتری (دسترسی فقط به باکت خودش)
- versioning + lifecycle + سرو از CDN آروان

### Redis مرکزی
- prefix `tenant:{id}:cache:*` / `session:*` / `queue:*`
- فقط داده «از دست رفتنی» (کش/سشن)

## 🔄 مهاجرت بین تیره‌ها (ارتقا)
```
Budget → Standard: pg_dump دیتابیس تِنت → pg_restore به PG جدید + ساخت منابع اختصاصی → آپدیت env → deploy
Standard → Enterprise: افزودن replica + resize منابع
```
- در پنل مرکزی به‌صورت «دکمه ارتقا تیر» (اسکریپت خودکار، بدون Downtime)

## 🚀 تأثیر روی اسکریپت نصب
`cms:new-client` تیره مشتری را می‌گیرد:
- Budget → ۲ کانتینر + دیتابیس روی PG مشترک + باکت MinIO + prefix Redis
- Standard → ۲ کانتینر + PG/Redis/MinIO اختصاصی
- جدول `install_versions` فیلد `tier` + `resource_registry` برای offboarding

## 🔒 بکاپ
| لایه | بکاپ |
|---|---|
| PG (اختصاصی مشترک) | خودکار چابکان + pg_dump شبانه به MinIO |
| MinIO | versioning + lifecycle |
| Redis | لازم نیست (کش‌محض) |
| **تست بازیابی** | ماهی یک‌بار در محیط آزمایشی ⬅ حیاتی‌ترین |

## ⚠️ قیدها
1. PG اشتراکی چابکان بکاپ ندارد → فقط PG **اختصاصی** مشترک استفاده شود
2. استخر سرویس فقط برای کانتینرهای stateless (Laravel/Next) در حالت stop (هزینه ۱/۳)
3. زامبی‌ها: ۲ هفته بی‌فعالیت → stop خودکار → ۳۰ روز → حذف (اگر API DELETE نداشت، حذف دستی)
