# چک‌لیست استقرار و راه‌اندازی

> هر مرحله‌ای که **خودکار نیست** اینجاست. اگر مرحله‌ای نبود و نبود، دیپلوی ناقص است.
>
> **قانون این سند:** هیچ فرمانی که «عمداً» خودکار نیست، نباید در استقرار جا بماند.
> چیزی که عمداً خودکار نیست ولی در راه‌اندازی لازم است، یعنی دارد در یک نشست
> زنده عیب‌یابی می‌شود — و این دقیقاً همان چیزی است که این سند برای جلوگیری از
> آن نوشته شده.

## پیش‌نیازها (نسخه‌های واقعی — `E10`)

| سرویس | نسخه | کجا pinned |
|---|---|---|
| PHP | **۸.۳** (CI) / ۸.۵ (کانتینر dev) | `composer.json` + CI |
| Laravel | **۱۳** (`^13.0`) | `composer.json` |
| PostgreSQL | **۱۸** | `docker/postgres/Dockerfile` |
| Redis | **۸** — ⚠️ **الزامی** | `docker-compose.yml` |
| MinIO | آخرین نسخهٔ ممکن — ⚠️ **الزامی برای مدیا** | `docker-compose.yml` |
| Node | ۲۰+ | `package.json` |

> **دو سرویسی که قبلاً در این چک‌لیست نبودند و نبودشان یعنی نصب نیمه‌کاره:**
> بدون Redis نه کشِ ISR/تنظیمات کار می‌کند نه نشست؛ بدون MinIO نه آپلود مدیا هست.
> دیپلویی که فقط همین سند را دنبال کند و آن‌ها را بالا نیاورد، سایت بالا می‌آید
> ولی **کش و مدیا بی‌صدا خراب‌اند**.

## ۱. متغیرهای محیطی

`PLUGIN_DDL_PASSWORD` **باید** در `.env` باشد و **نباید** رمز دیتابیس اصلی باشد.

نکته: این مقدار در `.env.example` توضیح داده نشده بود تا وقتی `B34` پیدا شد.

| متغیر | چرا لازم است |
|---|---|
| `PLUGIN_DDL_PASSWORD` | رمز نقش `pishdad_plugin_ddl` — جدا از کاربر اصلی دیتابیس |
| `MAIL_MAILER` | پیش‌فرض `failover` است: SMTP → log. برای ایمیل واقعی `smtp` + `MAIL_*` |
| `REDIS_*` | بدونش کش/نشست بی‌صدا از کار می‌افتند |
| `AWS_*` (MinIO) | مدیا |
| `REVALIDATE_SECRET` | purge کش فرانت. در production مقدار `change-me*` یعنی هرکس URL را حدس بزند کش را باطال می‌کند |
| `PLUGIN_PUBLISHER_SECRET_KEY` | مهرِ یکپارچگی بستهٔ افزونه/قالب؛ خالی ⇒ انتشار ناشر fail-closed |

### ۱.۱ کلیدهای `E2` / `E3` / `E4` (بدونِ اعتبارنامه)

این سه وابستگی **بدون کلیدِ واقعی کار نمی‌کنند** و اعتبارنامه‌شان در ریپو نیست، پس
ردیف‌های `E2`/`E3`/`E4` در `docs/TASKS.md` همچنان `pending` می‌مانند. آنچه اینجا
می‌آید قراردادِ **fail-closed** آن‌هاست: اگر درایورِ واقعی را انتخاب کنی و کلید را
ندهی، سیستم خطا می‌دهد و نامِ دقیقِ کلید را می‌گوید — به‌جای اینکه وانمود کند وصل است.

| ردیف | متغیر انتخابِ درایور | درایورها | کلیدهای لازم برای درایورِ واقعی |
|---|---|---|---|
| **E2** ایمیل | `MAIL_MAILER` | `log` · `failover` · `smtp` | `MAIL_HOST` `MAIL_PORT` `MAIL_USERNAME` `MAIL_PASSWORD` |
| **E3** پیامک | `SMS_DRIVER` | `null` (پیش‌فرض) · `log` · `panel` | `SMS_PANEL_URL` `SMS_PANEL_API_KEY` `SMS_PANEL_SENDER` |
| **E4** چابکان | `CHABOKAN_DRIVER` | `stub` (پیش‌فرض) · `api` | `CHABOKAN_API_TOKEN` `CHABOKAN_API_BASE` |

سه قاعده که این جدول را قابلِ اعتماد می‌کند:

1. **درایورِ بی‌خطر پیش‌فرض است.** `SMS_DRIVER=null` و `CHABOKAN_DRIVER=stub`. تا وقتی
   کسی عمداً `panel`/`api` نگذارد، هیچ کدام به شبکه دست نمی‌زنند.
2. **درایورِ واقعی + کلیدِ ناقص ⇒ exception با نامِ دقیقِ کلید** (پیام فارسی).
   یعنی حالتِ «فکر می‌کنم وصل است ولی نیست» ممکن نیست.
3. **درایورِ ناشناخته ⇒ برگشت به درایورِ بی‌خطر** (تا یک تایپ سایت را نبیندد)، ولی
   `pishdad:doctor` نامِ ناشناخته را گزارش می‌کند تا پنهان نماند.

> ⚠️ `MAIL_MAILER=failover` با کلیدِ خالی **کار می‌کند** ولی پیام‌ها فقط در لاگ می‌روند
> و هیچ‌کس آن‌ها را نمی‌بیند. `doctor` این را `warn` می‌دهد. `MAIL_MAILER=smtp` تنها با
> کلیدِ خالی `MISSING` است چون هر درخواست را تا `MAIL_TIMEOUT` (۱۰ ثانیه) معطل می‌کند.

### ۱.۲ `php artisan pishdad:doctor` — گزارشِ وضعیتِ همه چیز

این فرمان هر هشت وابستگیِ بیرونی را در یک نگاه می‌گوید: ایمیل، پیامک، چابکان،
MinIO/S3، Redis، نقشِ `pishdad_plugin_ddl`، کلیدهای مهر، و صفِ تحویل (outbox).

```bash
php artisan pishdad:doctor              # گزارشِ خوانا
php artisan pishdad:doctor --strict     # هر «warn» را هم خطا حساب کن (برای CI)
php artisan pishdad:doctor --json       # خروجیِ JSON برای پایشِ خودکار
```

سه حالت و معنای هرکدام — چون اگر همه یکی بودند اپراتور برای «پیامک نداریم و
می‌دانیم» هم کاری می‌کرد و بعد از دو هفته هشدار را نادیده می‌گرفت:

| حالت | یعنی چه | exit code |
|---|---|---|
| `ok` | همه‌چیز هست و کار می‌کند | 0 |
| `warn` | خاموشیِ **آگاهانه** (`null`/`log`/`stub`) یا چیزی با fallback دارد. سایت سالم است | 0 (و 1 با `--strict`) |
| `MISSING` | **تنظیمِ ناخواسته ناقص**: درایورِ واقعی انتخاب شده ولی کلیدش نیست | **1** |

> این فرمان عمداً **تلاش شبکه‌ای نمی‌کند** (جز Redis و S3 که ارزان و تشخیصی‌اند).
> دلیلش این است که یک `doctor` روی نصبِ بدون اینترنت نباید ۳۰ ثانیه معطل بماند و بعد
> بگوید «ناموفق». وجودِ کلید چیزی را ثابت می‌کند و برای اثباتِ کذب چیزی نمی‌خواهد.

> ⭐ این فرمان را **در CI یا مرحلهٔ پس از دیپلوی اجرا کنید**. `MISSING` یعنی دیپلوی
> نباید «موفق» اعلام شود. نمونهٔ خط فرمانِ دروست:

```bash
php artisan pishdad:doctor --json | grep -q MISSING && exit 1
```

## ۲. `php artisan migrate --force`

migrationها به ترتیب تاریخ اجرا می‌شوند. در نصب تازه این‌ها **الزامی‌اند** ولی در
فهرست قبلی جا نیفتاده بودند (یعنی پنل مرکزی یا بازار بی‌صدا از کار می‌افتاد —
و در فهرست افزونه‌ها معلوم نمی‌شد):

| migration | چه‌چیزی را بی‌صدا از کار می‌اندازد |
|---|---|
| `2026_10_08_000001_register_bundled_central_plugin` | پنل مرکزی + heartbeat نصب‌ها |
| `2026_10_12_000001_unlock_central_plugin` | بازگردانی پلاگین مرکزی از allowlist سیستمی |
| `2026_10_13_000001_register_subscription_plugin` | افزونهٔ «اشتراک من» ⇒ `/admin/subscription` خطا می‌دهد |
| `2026_10_13_000001_add_publisher_pin_to_system_plugins` | پین ناشر پلاگین سیستمی (امنیت L-B3) |
| `2026_10_14_000001_create_market_tables` | بازار: سفارش/لایسنس/ledger/payout |
| `2026_10_15_000001` + `2026_10_16_000001` | مهاجرت دادهٔ اشتراک به سطح نصب + ایندکس یکتا |

## ۳. `php artisan plugin-ddl:reset-password` — ⭐ این مرحله جا می‌افتاد

**این فرمان را حتماً اجرا کنید.** نبودِ آن باعث می‌شود **فعال‌سازی هر افزونه‌ای که جدول
می‌سازد** با این خطا رد شود:

```
نقش دیتابیسی «pishdad_plugin_ddl» آماده نشد
```

### چرا خودکار نیست

این تصمیم عمدی است و در `PluginDdlResetPassword.php:15-22` ثبت شده:

> بازنشانیِ خودکار یعنی هر بار که `.env` بازتولید شود (که در نصب تازه و در بعضی
> ابزارهای استقرار اتفاق می‌افتد) رمز دیتابیس هم عوض شود. تغییر پنهانِ دیتابیس از راه یک
> استقرار، بدتر از خطای صریحی است که آدم بخواند.

پس بازنشانی خودکار **نمی‌شود**. در عوض، خطا صریح است — ولی فقط اگر کسی بداند این
مرحله وجود دارد.

### فقط بررسی، بدون تغییر

```bash
php artisan plugin-ddl:reset-password --check
```

خروجی سالم:

```
نقش «pishdad_plugin_ddl» با رمز پیکربندی سالم است.
```

خروجی مشکل‌دار:

```
نقش «pishdad_plugin_ddl» هست ولی رمز پیکربندی به آن وصل نمی‌شود.
```

### اجرا

```bash
php artisan plugin-ddl:reset-password
```

این فرمان رمز نقش را از `PLUGIN_DDL_PASSWORD` در `.env` **می‌خواند** و روی نقش در
PostgreSQL **می‌نویسد**. نیازی به ویرایش دستی `.env` نیست.

> ⚠️ اگر `.env` شما رمز **تست** دارد (مثل `test-only-ddl-secret`)، این فرمان همان رمز
> تست را روی نقش می‌نویسد. اول `PLUGIN_DDL_PASSWORD` را مقدار واقعی بگذارید.

## ۴. `php artisan outbox:drain` — ⚠️ بدون caller است

صندوق ایمیل/پیامک (`notification_deliveries`) هیچ caller خودکاری ندارد. تا وقتی
فرمان بالا (مرحلهٔ ۰) نباشد، نه ایمیلی می‌رود نه رکوردها پاک می‌شوند.

```bash
php artisan outbox:drain        # اجرای دستی برای بررسی
```

پیامک و push طبق تصمیم Q7 **عمداً** `failed` می‌شوند تا وقتی provider داشته باشند.

---

## ۵. `php artisan plugin-seal --reseal` — فقط برای نصب‌های قدیمی

مهر یکپارچگی (K5.2-W) روی **فایل‌های استخراج‌شده** زده می‌شود. نصب‌هایی که **قبل از
این** ساخته شده‌اند مهر ندارند ⇒ `activate` آن‌ها را با پیام روشن رد می‌کند.

```bash
php artisan plugin-seal --all --reseal     # یک‌بار برای ارتقای نصب قدیمی
```

> نصب تازه نیازی ندارد: `PluginInstaller` خودش مهر را می‌زند.

## ۶. تأیید

```bash
php artisan pishdad:doctor                        # ⭐ اول: هر وابستگی بیرونی، با exit code
php artisan plugin-ddl:reset-password --check    # باید «سالم» بگوید
php artisan migrate:status                       # نباید Pending بماند
php artisan backup:run --dry-run                 # pg_dump در دسترس است؟
php artisan outbox:drain --dry-run               # صندوق خراب نیست؟
```

> ⭐ `pishdad:doctor` را **اول** بگذارید چون چیزهایی را می‌گوید که هیچ فرمان دیگری
> نمی‌گوید: اینکه ایمیل واقعاً می‌رود یا فقط در لاگ می‌افتد، و اینکه پیامکی در صف نمانده.
> اگر `MISSING` داد، دیپلوی را «موفق» اعلام نکنید.

سپس در پنل: فهرست افزونه‌ها باید **«مرکز»** و **«اشتراک من»** را نشان دهد، و
فعال‌سازی یک افزونهٔ جدید نباید خطای DDL بدهد.

## چه چیزهایی عمداً خودکار نیستند

| چیز | چرا |
|---|---|
| `plugin-ddl:reset-password` | تغییر پنهانِ رمز دیتابیس هنگام استقرار، بدتر از خطای صریح است |
| `plugin-seal --reseal` | مهر یکپارچگی باید یک‌بار پس از ارتقا زده شود، نه در هر استقرار |
| `SET LOCAL ROLE` | جداسازی نمی‌دهد؛ `PluginRouteTable` و اتصال جدا لازم است |
| امضای ناشر | فقط از راه بازار معتبر است — آپلود مستقیم نیاز به `dev_mode` دارد |
| ایمیل/پیامک | بدون credential از `config/mail.php` به log می‌رود (F0.10) و `sms` صریحاً `not_configured` می‌گوید (F0.4) |
| `pishdad:doctor` | فقط **گزارش** می‌دهد، تنظیم را «درست» نمی‌کند — جای تصمیم مالک نیست |
